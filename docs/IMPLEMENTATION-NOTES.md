# Android checkpoint implementation notes

This is an incremental PR, not a completed P0 release. Requirements remain in PRD.md.

## Current contracts

- Version 1 pure Dart geometry uses a 96-column, eight-beat occupancy grid and C3–C6 pentatonic ladder. Segment/bin intersections preserve vertical polyphony and multiple branches; equal instrument/pitch/bin occupancy is unioned. Export and preview compile the same immutable document to a sorted ScoreSnapshot.
- The original additive renderer produces 44.1 kHz mono PCM16. Three distinct harmonic/envelope formulas are versioned in source. Soft limiting and attack/release ramps bound samples. Native AudioTrack plays one precomputed loop, including folded release tails, without Dart note timers. The cursor reads the hardware playback head; a 50 ms Dart poll only updates its position. WAV contains one loop followed by a bounded 1.25 s tail; the active release is 0.18 s, so some of that tail is silence. MIDI contains score notes with documented GM substitutes, not identical synthesized timbres.
- Android audio focus loss, noisy-route broadcast and Activity pause pause AudioTrack; foregrounding never automatically starts it. Pause/resume retains position; Replay prepares from zero. Native behavior is compiled but not exercised on a device here. No physical latency, timbre or interruption claim follows from file rendering.
- **Interim transport limitation:** any committed drawing/music edit pauses playback and invalidates prepared audio. PRD F08/F09 require loop/beat-boundary updates. That scheduler is still pending, and M2 is not accepted complete.
- Persistence uses app-private immutable checksummed JSON revisions with flush → atomic rename and serialized saves, retaining three complete revisions. This implements a small file-backed repository port rather than the proposed SQLite/Drift metadata index. Newest valid revision wins, stale saves are ignored, incomplete `.tmp` files never load, and a corrupt newest revision falls back. A listing isolates corrupt projects. Schema/engine version 1 is the only published version; unknown versions are rejected without modifying the original. Directory fsync/power-loss durability is not guaranteed by Dart's file API; force-stop/low-storage behavior still needs Android tests. Recovery currently does not display a separate “older revision recovered” banner.
- Autosave after 500 ms, explicit Save, lifecycle save and guarded Back use the same queue. Saved status is shown only after repository completion; failure retains the editor and offers Retry. Titles, strokes, width, instrument assignments, tempo, scale and paper color reopen. Current tool/selection, user preferences and a resumable editor route are not persisted yet.
- Eraser clips polyline segments against a swept disk and publishes one history operation per gesture. Empty erasing is a no-op. History retains at most 100 commands and a conservative shared-geometry budget. At 100,000 points, input stops with feedback; automatic geometry simplification/performance profiling remains pending.
- MIDI/WAV rendering runs in an isolate, freezes revision/settings and publishes by atomic rename. Cancel suppresses publication and deletes temporary files; a running isolate finishes its bounded render before cancellation completes. Share is explicit after completion. Canceled/unavailable share results do not imply delivery. Exports currently remain in app-private documents storage and can be shared immediately; a persistent exported-library UI and artifact metadata index are pending.

## Remaining roadmap work

M0 is complete. M1's core editing is implemented/tested; large-scene/smoothing tuning remains. M2's compiler and actual Android adapter exist; scheduling and device acceptance are pending. M3's core save/reopen/recovery paths are tested; library rename/duplicate/delete, recovery banners and process-death acceptance remain. M4 is partial: tested MIDI/WAV + share adapter; **MP4 has not been implemented** and no MP4 success is represented in the UI. M5 remains open (settings persistence/tutorial, accessibility review, performance/soak, lifecycle/device QA, localization infrastructure).

Implement a native Android MediaCodec/MediaMuxer video adapter using the same frozen document/score/rendered audio next; do not substitute a screen recording, fake export or research media. Its exit gate requires inspected H.264/AAC output with exact canvas aspect and A/V duration, cancellation cleanup and device playback. iOS audio/encoding adapters still need implementation and local Mac testing, beyond merely creating iOS scaffold files.
