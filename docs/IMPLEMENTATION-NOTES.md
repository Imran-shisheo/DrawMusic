# Android checkpoint implementation notes

This is an incremental PR, not a completed P0 release. Requirements remain in PRD.md.

## Current contracts

- Version 1 pure Dart geometry uses a 96-column, eight-beat occupancy grid and C3–C6 pentatonic ladder. Segment/bin intersections preserve vertical polyphony and multiple branches; equal instrument/pitch/bin occupancy is unioned. Export and preview compile the same immutable document to a sorted ScoreSnapshot.
- The original additive renderer produces 44.1 kHz mono PCM16. Three distinct harmonic/envelope formulas are versioned in source. Soft limiting and attack/release ramps bound samples. Native AudioTrack streams precomputed loops, including folded release tails, without Dart note timers. The cursor reads the hardware playback head; a 50 ms Dart poll only updates its position. WAV contains one loop followed by a bounded 1.25 s tail; the active release is 0.18 s, so some of that tail is silence. MIDI contains score notes with documented GM substitutes, not identical synthesized timbres.
- Android audio focus loss, noisy-route broadcast and Activity pause pause AudioTrack; foregrounding never automatically starts it. Pause/resume retains position; Replay prepares from zero. The API 35 emulator exercises the real clock, beat/loop updates and pause/resume. Physical focus/route/background behavior is still untested. No physical latency, timbre or interruption claim follows from file rendering.
- **Current transport update:** MODE_STREAM consumes pre-rendered immutable PCM through a bounded native writer. Geometry/scale/history revisions switch at the next available loop boundary; tempo-only changes switch at the next available beat while preserving phase. A 128-frame crossfade bounds handoff discontinuity. The playback-head timeline reports audible revisions, not queued writes. Late preparation can miss an already queued boundary; the pending badge remains until the first available boundary is audible. Device validation of this new adapter and pause/focus ramps is pending.
- Persistence uses app-private immutable checksummed JSON revisions with flush → atomic rename and serialized saves, retaining three complete revisions. This implements a small file-backed repository port rather than the proposed SQLite/Drift metadata index. Newest valid revision wins, stale saves are ignored, incomplete `.tmp` files never load, and a corrupt newest revision falls back. A listing isolates corrupt projects. Schema/engine version 1 is the only published version; unknown versions are rejected without modifying the original. Directory fsync/power-loss durability is not guaranteed by Dart's file API; force-stop/low-storage behavior still needs Android tests. Recovery now displays an older-revision notice in Drafts and Editor; replaced damaged bytes are preserved separately.
- Autosave after 500 ms, explicit Save, lifecycle save and guarded Back use the same queue. Saved status is shown only after repository completion; failure retains the editor and offers Retry. Titles, strokes, width, instrument assignments, tempo, scale and paper color reopen. Current tool/selection, user preferences and a resumable editor route are not persisted yet.
- Eraser clips polyline segments against a swept disk and publishes one history operation per gesture. Empty erasing is a no-op. History retains at most 100 commands and a conservative shared-geometry budget. At 100,000 points, input stops with feedback; automatic geometry simplification/performance profiling remains pending.
- MIDI/WAV rendering runs in an isolate, freezes revision/settings and publishes by atomic rename. Cancel suppresses publication and deletes temporary files; a running isolate finishes its bounded render before cancellation completes. Share is explicit after completion. Canceled/unavailable share results do not imply delivery. Exports currently remain in app-private documents storage and can be shared immediately; a persistent exported-library UI and artifact metadata index are pending.

## Remaining roadmap work

M0 is complete. M1's core editing is implemented/tested; large-scene/smoothing tuning remains. M2's compiler and native boundary scheduler exist; the owner confirmed the prior static adapter produces sound. The new streaming adapter and interruption/latency behavior still need device acceptance. M3's core save/reopen/recovery paths are tested; library rename/duplicate/delete with Undo and recovery banners are implemented; process-death acceptance remains. M4 now includes the Android MP4 adapter alongside MIDI/WAV and native sharing. Native AudioTrack and MediaCodec/cancellation tests pass on the API 35 emulator. The full offline UI save/reopen/export flow and independent H.264/AAC/MIDI/WAV timing checks pass in 1.2.1+5. Receiving-app sharing and physical-device acceptance remain pending. M5 remains open (settings persistence/tutorial, accessibility review, performance/soak, lifecycle/device QA, localization infrastructure).

The Android MediaCodec/MediaMuxer adapter uses the same frozen document/score/rendered audio; it does not record the screen or microphone. HD is 1080×1350, compact 640×800, both 30 FPS with H.264/AAC. Leaving the foreground cancels video rendering. The encoder and UI native bridge pass the API 35 emulator tests in 1.2.1+5. AAC priming is measured from decoded output and whole priming packets are trimmed; padded encoder input preserves the release tail. Independent correlation measured zero audio offset for both tested resolutions. Its exit gate requires inspected H.264/AAC output with exact canvas aspect and A/V duration, cancellation cleanup and device playback. iOS audio/encoding adapters still need implementation and local Mac testing, beyond merely creating iOS scaffold files.

Physical acceptance steps are tracked in [ANDROID-ACCEPTANCE.md](ANDROID-ACCEPTANCE.md), with unperformed checks explicitly pending.


## Preferences and guide

Version 1.3.0+6 adds a local checksummed preference repository for preview volume, optional haptics, reduced motion and tutorial completion. Writes retain a valid backup and preserve damaged primary bytes before repair. The controller publishes saved values only after persistence succeeds and exposes errors/retry. Preview volume uses AudioTrack output gain only; offline export rendering retains its original level. The welcome guide is skippable and replayable, with safe-area actions independent of content scrolling. Reduced page transitions follow the app or system preference; essential timing cues remain. Actual version information comes from package_info_plus. Physical feedback/lifecycle acceptance, contextual tool tips and localization remain pending.


## Export catalog and public copies

Version 1.4.0+7 scans completed app-private MIDI/WAV/MP4 files and writes bounded checksummed sidecars after successful publication. Thumbnail-only simplification never changes the editable drawing or score. Missing/damaged details preserve files and allow legacy discovery. Names are display metadata; renaming leaves encoded bytes intact. Deletion retains a seven-second tombstone for six-second UI Undo, then purges on listing; public/shared copies are outside this lifecycle. Older status snackbars are cleared before Undo.

Android file actions validate canonical export-root paths, MIME and safe display names. Open copies only the chosen export into a dedicated cache directory exposed through a read-only URI. API 29+ public saving uses MediaStore IS_PENDING and verifies copied byte counts/file size before publication. API 24–28 uses ACTION_CREATE_DOCUMENT; cancellation is explicit and partial-destination cleanup is best effort where document providers permit deletion. A successful chooser launch is not a delivery/playback claim. Receiving-app behavior and legacy provider paths still require device QA. iOS native file actions remain pending alongside audio/video adapters.
