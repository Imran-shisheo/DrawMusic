# Explicit expression and stylus input

Geometry-only music remains the default. Merely drawing with a pen or opening an older project does not enable speed/pressure dynamics. `ProjectDocument.expressionMode` is an explicit, persisted and undoable `geometry` / `expressive` selection. Expressive selection upgrades the document and sound versions to 2; previous version-1 documents retain their mode, note velocity, geometry and original three-number point encoding. Returning a version-2 document to geometry mode does not erase already saved version metadata.

`InkPoint.input` optionally records normalized pen pressure (0–1), pen tilt (0–π/2 radians) and a stable device-kind code. Canvas pointer events normalize pressure from the reported pressure minimum/maximum; invalid/unsupported ranges remain absent. Touch input remains the old `[u,v,ms]` representation. Pen, mouse or other optional metadata uses `[u,v,ms,pressureOrMinus1,tiltOrMinus1,kindCode]`. Device-kind codes are append-only: 0 touch, 1 mouse, 2 stylus, 3 inverted stylus, 4 unknown. Unknown future numeric codes up to 255 round-trip unchanged while resolving to the safe unknown display behavior. Metadata-only geometry documents use schema 2 but may retain sound engine 1.

One active pointer still owns a drawing gesture. A second touch or pen is ignored; selecting another tool safely finishes the original gesture. A platform's inverted-stylus device kind is recorded as metadata; it does not silently switch the selected drawing tool or erase work. Pen side-button shortcuts and pressure-dependent line width are not claimed. Unsupported hardware simply provides geometry/timestamps and follows the selected mode's documented fallback.

Erasing interpolates timestamps, pressure and tilt for new clip endpoints while preserving source device kind. Retained simplification anchors preserve their original metadata. The simplification acceptance check compares note velocities/gains as well as pitch/timing, so it cannot silently change an expressive score just to reduce points. History accounts the larger optional point footprint and compares all metadata fields. Save, reopen and duplicate retain metadata and explicit mode.

The exact velocity rule and export agreement are implemented by the pure Dart score compiler and shared audio/MIDI export paths, not widget timers or a platform-specific note loop. See the score implementation/tests for the final deterministic policy. Mode selection applies through the existing transport revision boundary. Background changes remain nonmusical.

Portable tests cover old-point byte stability, metadata-only schema/sound separation, pressure/tilt validation, future device-code preservation, explicit mode persistence and Undo/Redo, interpolated erasure endpoints and actual Flutter native-style pen pointer events including ignored second touches. These tests do not establish real Android stylus sampling quality, iPad Pencil behavior, force/tilt calibration, audio latency or physical accessibility acceptance. Those remain device QA.
