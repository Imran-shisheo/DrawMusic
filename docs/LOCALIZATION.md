# English localization foundation

The MVP ships English (`en`). Settings → Language opens a scrollable selector with an explicit check and Apply/Cancel. Only a shipped language is listed. Applying writes preferences before returning to Settings; failure stays retryable on the selector. Unsupported/missing saved languages and unsupported device locales fall back to English without changing unrelated preferences or drawing data. The router is retained across locale rebuilds so the selected root tab and loaded page states survive.

Interface resources live in `lib/l10n/app_en.arb`; Flutter generates committed classes under `lib/l10n/generated`. Material/Cupertino/widget localization delegates are installed on the application. `context.strings` also provides English in isolated reusable control hosts without delegates. The catalog covers root navigation, core editor/transport/style/paper controls, contextual guidance, settings and library/export actions, plus parameterized score/export summaries. Some operational/native failure strings and dynamic status messages still use English directly; migrate those presentation mappings before introducing another translation. This checkpoint establishes infrastructure and does not claim a fully translated secondary locale.

User titles, project IDs, stroke coordinates, score values, checksums and standard MIDI/WAV/MP4 data are never localized. Display helpers group numbers and format UTC timestamps in local time with the active UI locale; byte encoders retain numeric values and standard formats. Draft/export metadata and file names remain independent of language selection. User-provided non-Latin and RTL titles remain data and are not looked up as translation keys.

To change messages, edit the English ARB and placeholder metadata, run `flutter gen-l10n`, then run `dart format lib test integration_test tool` and the product check script. Generation also runs through Flutter's normal dependency/build flow. Before adding a P1 locale, translate and review all required messages and error mappings, add its native language name and saved-code normalization/selector choice, then run language, layout, format and device checks. Do not list an untranslated locale as available.

Automated tests cover missing/unsupported saved-language recovery through real files, an unsupported device locale, Apply/Cancel and write failure/retry, unchanged non-Latin/RTL drawing data, retained Library/Settings navigation, English date/number formatting, and a 320 dp / 200% text RTL selector with reachable actions. Actual TalkBack and complete application RTL/device acceptance remain open; no RTL translation ships in this checkpoint.
