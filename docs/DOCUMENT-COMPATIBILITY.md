# Document compatibility and explicit sound versions

Version-1 is the actual released format, represented by `test/fixtures/project_v1_music.json`, generated from main fd5074a. `project_v1_pcm_hashes.json` records complete WAV SHA-256 hashes generated by that source's original renderer for all three original voices. These are genuine prior-format fixtures; no nonexistent version-0 format or migration test is invented.

Opening or saving existing v1 content retains schema 1, engine 1, original scale IDs, original geometry and exact rendered PCM. A new root, expanded family, expanded instrument or configured accompaniment opts the document into schema/engine 2. Merely selecting a visual background opts into schema 2 while retaining the audio-engine version. Version getters `formatVersion` and `soundVersion` are independent of the static `schemaVersion`/`engineVersion` historical-baseline constants. Once a version-2 document is edited back to legacy settings it remains version 2, avoiding deceptive downgrade. No automatic sound migration of existing content occurs.

Recognized stable IDs resolve normally. An unknown instrument resolves to Cloud keys for safe playback and painting, while `Stroke.instrumentId` preserves the original ID. Unknown scales and roots similarly resolve to C major pentatonic with `scaleId`/`rootId` retaining the original values. The document exposes explicit fallback flags and unknown IDs for a labeled compatibility notice. Unknown top-level and stroke JSON metadata is retained, deeply frozen, and written back. Geometry clipping and simplification must use `Stroke.copyWith` to retain that metadata. Only explicitly selecting a replacement instrument/root/scale replaces its raw unknown ID. Future unsupported schema or engine versions still fail closed; the repository preserves original bytes and existing recovery/export paths remain available.

Unknown values are not proof of a missing commercial asset: this catalog uses self-contained original synthesis and has no required external sample packs. Photo/background asset availability is a separate check. Data that cannot be decoded is never silently represented as an empty saved project.

Tests in `document_compatibility_test.dart` exercise unknown IDs, nested metadata, fallback scoring, editing, erasing and save/reopen; future schema/engine rejection also verifies unchanged original file bytes. Existing persistence/retention tests continue to cover corrupt revisions and transactional recovery. These tests do not establish Android low-storage/power-loss, physical sharing or iOS behavior.
