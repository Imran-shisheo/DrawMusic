# Shipped translation resources

This creative-expansion checkpoint supplies English (`en`) plus French (`fr`), Spanish (`es`), Italian (`it`), Korean (`ko`), Japanese (`ja`), Vietnamese (`vi`), Hindi (`hi`), Portuguese (`pt`), Thai (`th`), Filipino/Tagalog (`fil`) and Indonesian (`id`). Language selection shows native names, stages a pending choice and persists only on Apply. Cancel and platform Back preserve the saved locale. Unsupported or missing saved identifiers fall back to English without losing other preferences.

Every shipped locale explicitly supplies every English ARB key, including operational failures, guides, catalog labels, photo/camera guidance, export states, accompaniment and expressive/theme controls. Generated Flutter localization subclasses are checked in. Standard formats/acronyms, musical mode loanwords and the original product name remain stable where appropriate. User-created titles, paths, MIDI/WAV/MP4/PNG bytes and persisted document identifiers are never translated. Display numbers and dates use the selected locale independently of stored UTC timestamps and numeric data.

Android system pickers are system-localized; the app-provided exported-file chooser title has native Android resources for every shipped locale. Indonesian uses Android's `values-in` qualifier and Filipino uses BCP-47 `values-b+fil`. iOS camera permission purpose text is supplied in each locale's `InfoPlist.strings`; source integration and Mac compilation are tracked by the iOS implementation documentation. Internal native diagnostics remain codes that map to localized Flutter guidance rather than displaying exception text.

These are newly authored machine-assisted translations. They have **not** undergone native-speaker linguistic review. Key completeness, placeholders, localized operational states, persistence and responsive controls can be verified automatically; naturalness, regional terminology and screen-reader pronunciation require human review. No claim of human-reviewed translation quality is made.

`test/translations_test.dart` checks all twelve resource sets, interpolation parity, persistence of every supported language, native resource presence and a compact 320×640 / 200% text language-selection flow for every locale. The existing localization regression covers transactional Cancel/Apply, saved Unicode drawing data, unsupported fallback, failed-save retry and RTL directionality. RTL testing is layout coverage; no RTL language is added by this task. Physical TalkBack/VoiceOver, actual system dialogs and device font rendering remain pending until tested.

To regenerate after changing any ARB, source `cloud/env.sh` and run `flutter gen-l10n`. Add every new key to **all twelve** ARBs, preserving interpolation names and types, then run `flutter test test/localization_test.dart test/translations_test.dart`. Do not use an English fallback as evidence that a translation is implemented.

The 27 October UI redesign adds explicit resources in every shipped locale for intent-led export/library copy, settings sections, paper/crop interactions and focused editor panels. Welcome uses the interpolated `welcomeToBrand(name)` resource supplied with the centralized brand definition; legacy getter names remain compatible. Current display-name values use the owner's confirmed Doodimo name, while user-authored titles and storage/package identifiers remain unchanged. The bundled offline font stack and actual codepoint checks are documented in FONT-PROVENANCE.md. Real-font UI stills and strict three-screen golden comparisons are additional evidence, not human linguistic or physical accessibility acceptance.
