Redesign DrawMusic’s complete UI/UX and motion experience.

The owner likes the application’s functionality but strongly dislikes the
current presentation and interaction design. UI/UX is now a primary product
priority.

Implement a cohesive, beautiful, soothing creative experience with:
- Smooth animated navigation
- Elegant transitions throughout the app
- Original ambient background motion graphics
- Consistent branding
- Clear visual hierarchy
- Comfortable typography and spacing
- Intuitive controls and progressive disclosure
- Polished interaction feedback
- Excellent drawing and audio responsiveness

This is an implementation request. Review, design, implement, render,
test, refine, and deliver working Flutter code. Continue beyond planning
or producing mockups.

1. AUTHORIZATION AND SCOPE

This request authorizes replacing the previous visual layouts and motion
specifications where needed to achieve the new direction.

Preserve all functional PRD requirements, project compatibility, audio
behavior, editing behavior, recovery, exports and accessibility.

Read AGENTS.md and applicable nested instructions first.

Keep all creative features free.

Ads, billing, accounts, servers, uploads, paid infrastructure and cloud
collaboration remain excluded.

Leave reviewable draft PRs UNMERGED. Do not publish to stores, force-push,
operate the owner’s personal phone, or schedule future tasks.

Android is the executable cloud target. Keep the presentation portable
to iOS. Do not claim iOS compilation or device validation from Linux.

Do not introduce remote assets or runtime network dependencies for the UI.

3. DESIGN DIRECTION

Create an original “calm musical sketchbook” identity.

Desired feeling:
- Creative, warm and inviting
- Quietly playful
- Clear and uncluttered
- Tactile and carefully composed
- Visually refined
- Comfortable during long creative sessions

Use a continuous drawn line becoming a musical wave as the central visual
motif. Carry this motif through the mark, onboarding illustrations, empty
states, subtle page graphics and motion.

Use composition, hierarchy, spacing and interaction design to create polish.
A palette change or rounded corners alone will not satisfy this task.

Keep the current working display name consistent through a centralized
brand definition. ScribbleSong is provisional and DrawMusic is the
repository name. Do not invent a permanent store-name decision or change
the application identifier.

Preserve com.imranshisheo.scribblesong.

Create reusable tokens/components for:
- Brand identity and mark
- Semantic light/dark colors
- Typography
- Spacing and layout
- Radii
- Borders and elevation

5. CREATE A SHARED MOTION SYSTEM

Define motion centrally and use it throughout the app.

Suggested starting values:
- Press feedback: 90–140 ms
- Selection changes: 160–220 ms
- Root-tab content transition: 240–280 ms
- Forward navigation: 300–360 ms
- Back navigation: approximately 220–280 ms
- Sheets: 280–340 ms
- Shared drawing-to-editor transition: 360–440 ms
- Small first-entry stagger: 20–35 ms between a few elements
- Ambient background cycle: approximately 12–20 seconds

Refine these values through visual review. They are proposed design values,
not measured requirements.

Motion should:
- Explain where content came from and where it goes
- Make hierarchy and selected state understandable
- Respond promptly to input
- Reverse naturally on Back
- Survive rapid repeated actions
- Finish cleanly without visual snapping
- Preserve focus and interaction state

Use gentle easing and restrained, well-damped settling where appropriate.
Keep drawing targets, readable text and controls stable during interaction.

Every important interaction should have coherent feedback. Continuous
movement belongs in quiet decorative areas, not every control.

6. REDESIGN NAVIGATION

Keep Home, Library and Settings clear and consistently reachable.

Create a refined shared navigation dock with:
- Clear selected icon and label
- A smoothly moving selection treatment
- Comfortable touch targets
- A deliberate New Drawing action
- Proper safe-area spacing
- No overlap with scrolling content

Animate root-tab content with a subtle fade and short directional movement.
Preserve each branch’s navigation, scroll and state.

Important:
Do not replace the stateful navigation structure with an AnimatedSwitcher
that disposes and recreates branches on every selection.

Preserve:
- Drafts/Exports section selection
- Scroll positions
- Pending language selection
- Dialog ownership
- Editor origin and safe Back behavior
- Project/controller lifetimes

Handle rapid tab switching, Back during transitions, keyboard visibility,
and reduced motion.

Use shared-element transitions between a template/draft preview and the
editor canvas where this is visually and technically sound.

Use unique hero identities, avoid duplicate heroes in retained branches,
and animate a safe snapshot rather than rebuilding the live drawing/audio
engine during every animation frame.

Native share sheets, camera, photo pickers and document providers remain
OS-owned interactions.

7. ADD ORIGINAL AMBIENT BACKGROUND MOTION

Implement a subtle line/wave-based ambient visual system.

Appropriate treatments:
- Slowly drifting original curved paths
- A quiet line gradually becoming a wave
- Very subtle tonal movement behind a hero illustration
- Small original decorative marks with restrained movement

Use it selectively on Home, welcome/help and empty-state surfaces.
Settings may use a very quiet static or minimally animated treatment.

Requirements:
- Keep content and text on stable, readable surfaces.
- Confine decoration to purposeful regions.
- Use bounded, lightweight rendering.
- Pause offscreen and in the background.
- Respect reduced motion.
- Avoid continuous battery-heavy effects.
- Exclude decorative elements from semantics and hit testing.
- Freeze or suppress decorative movement during active drawing when needed.
- Preserve clear focus during playback and export.

App-level motion graphics must never become part of saved drawings,
thumbnails, PNGs or MP4 document exports.

If a visual reacts to music, derive its timing from the real audio clock.
Do not invent a fake waveform, audio meter or independent beat scheduler.

- One immediately discoverable Start Drawing action

9. REDESIGN THE EDITOR AROUND THE CANVAS

The drawing and its sound are the main experience.

Create a calmer hierarchy:
- Compact header: Back, readable project title, quiet save state and Export
- Generous stable canvas
- Immediately reachable Draw/Erase and Undo/Redo
- Clear current instrument and an elegant instrument chooser
- Prominent Play/Pause with accessible Replay
- Compact tempo/key/scale summary
- Progressive disclosure for accompaniment, paper, style and expression

At normal phone sizes, give the canvas the largest practical share of the
workspace. Do not shrink it unnecessarily to display every advanced control.

Keep important actions reachable at 320 dp and 200% text. Adapt layout
rather than clipping labels or reducing text/touch-target sizes.

Replace the long instrument-chip strip with a refined solution:
- Clearly visible current voice
- Named, color-linked instrument tiles
- Efficient access to all 13 voices
- Selected check/outline plus label
- A compact dock or well-designed chooser
- No reliance on color or tiny icons alone

Use a subtle, responsive selection transition. Selecting an instrument
must preserve previous strokes and safely finish an active gesture.

For music settings:
- Show readable current values
- Use a focused, branded key/scale selector
- Keep tempo changes easy
- Put accompaniment/mix controls in a coherent panel
- Explain expression briefly without occupying permanent canvas space

For playback:
- Smooth Play/Pause icon/state transition
- Honest preparation state
- Gentle, readable active-note feedback
- Audio-clock-owned cursor
- Quiet “updates next loop/beat” and save indicators

Do not delay pointer capture or sound preparation to finish decorative
animations. Do not remount the canvas or reset an active gesture during
layout/selection animation.

11. REDESIGN LIBRARY AND EXPORT

Library:
- Cohesive Drafts / Exports segmented navigation
- Recognizable document thumbnails
- Readable names and dates
- Clear artifact-type badges
- Consistent overflow actions
- Attractive, useful empty states
- Honest missing/corrupt/recovery states

Preserve rename, duplicate, delete/Undo, raw recovery and public file actions.

Export:
Replace the long sequence of controls with a clear selection flow.

Present four intent-led options:
- Image — PNG
- Sound — WAV
- Video — MP4
- Notes — MIDI

Each option needs:
- A recognizable icon
- A concise explanation
- Clear selected state

Show only the relevant settings for the selected format, then one clear
primary Export action.

Keep MIDI’s different playback/timbre behavior understandable.

Animate changes between:
- Format selection
- Format options
- Preparing/rendering/finalizing
- Ready
- Error/retry
- Cancellation

Use actual progress and honest indeterminate states. Do not animate fake
completion, display success before publication, or equate opening a share
sheet with delivery.

Success should present the real artifact with useful Share, Save and Open
actions, using restrained confirmation feedback.

Keep export job ownership and cancellation correct during route/sheet
animations. A decorative transition must not accidentally cancel a valid
job or leave it detached from the UI.

13. ACCESSIBILITY AND RESPONSIVE REQUIREMENTS

Support:
- Light and dark themes
- All 12 shipped languages
- Long/non-Latin/RTL content
- 200% text
- 320 dp phones through tablets
- Portrait/landscape
- Safe areas, keyboards and system navigation bars

Measure:
- Normal-text contrast of at least 4.5:1
- Appropriate large-text and non-text contrast
- Touch targets of at least 48 dp where required by the Android design
- Clear selected/disabled/error states

Reduced motion must remove decorative loops, large translations, parallax
and unnecessary shared-element movement. Keep a clear static/essential
playback position and equivalent usable state changes.

Honor motion preferences in custom route containers, sheets, animated
icons and background painters—not only the page-transition theme.

Keep semantics and focus stable during transitions. Avoid announcing
decorative graphics or duplicated outgoing/incoming page content.

14. PERFORMANCE AND ARCHITECTURE

Use the pinned Flutter SDK and inspect APIs compatible with the repository.

Prefer Flutter-native animation and original vector drawing. Add a
dependency only when its benefit and license are clear.

Keep animation state local. Do not update the whole Riverpod project,
serialize geometry or rebuild the entire editor on every animation tick.

Keep canvas, pointer preview, playback cursor and ambient graphics in
separate repaint paths.

Pause hidden-branch/background tickers. Dispose controllers/listeners.
Use lazy lists/grids and bounded image decoding.

Avoid expensive full-screen blur, unnecessary offscreen layers and
animation-driven heavy layout work.

Profile actual transitions and drawing under load. Target the appropriate
frame budget for the tested refresh rate and report measured UI/raster
timings and dropped frames. A debug screenshot or passing widget test
does not prove smooth physical performance.
